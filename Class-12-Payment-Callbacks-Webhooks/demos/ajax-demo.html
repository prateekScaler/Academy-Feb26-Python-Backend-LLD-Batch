AJAX Deep Dive

XMLHttpRequest vs fetch() vs axios — What's the difference and why "asynchronous"?

What is AJAX?

AJAX = Asynchronous JavaScript And XML

A technique to send HTTP requests from JavaScript without reloading the page. Despite the name, we use JSON today, not XML.

Before AJAX (1990s)

Every action required a full page reload. Click "Add to Cart" → entire page reloads.

After AJAX (2005+)

Click "Add to Cart" → only the cart icon updates. The rest of the page stays the same.

HTTP Timeout — The Key Constraint

Default Timeouts:

  • Browser (fetch/XHR): No default timeout (waits forever) — but users won't wait!
  • Server (nginx): 60 seconds default
  • Server (Django): 30 seconds (gunicorn default)
  • API Gateway: 30 seconds (AWS API Gateway)
  • Load Balancer: 60 seconds (AWS ALB)

Bottom line: If your request takes > 30 seconds, something will timeout.

This is why payment processing can't use simple request-response. Bank verification can take 30+ seconds, and the user might be entering OTP for 2 minutes.

Why is it called "Asynchronous"?

Common confusion: "If we're waiting for the response, how is it asynchronous?"

The key is what happens while waiting:

Synchronous (Blocking)

1. Send request

2. WAIT... (blocked)

Can't do anything else. UI frozen.

3. Receive response

Asynchronous (Non-blocking)

1. Send request

2. Continue execution

UI responsive, animations work, user can scroll

3. Callback fires when done

Key insight: "Asynchronous" doesn't mean "instant" — it means the browser doesn't freeze while waiting. The JavaScript event loop continues, animations play, and the user can interact with the page.

Live Comparison: XMLHttpRequest vs fetch vs axios

All three do the same thing — make HTTP requests. Click "Run" to see each in action. We're calling jsonplaceholder.typicode.com (a free fake API).

XMLHttpRequest Old Way (2005) 
const xhr = new XMLHttpRequest();
xhr.open('GET', 'https://jsonplaceholder.typicode.com/posts/1');

xhr.onload = function() {
    if (xhr.status === 200) {
        console.log('Success!', JSON.parse(xhr.responseText));
    } else {
        console.error('Error:', xhr.status);
    }
};

xhr.onerror = function() {
    console.error('Network error');
};

xhr.send();
Click "Run" to see output...
fetch() Modern (2015+) 
try {
    const response = await fetch('https://jsonplaceholder.typicode.com/posts/1');

    if (!response.ok) {
        throw new Error(`HTTP error: ${response.status}`);
    }

    const data = await response.json();
    console.log('Success!', data);
} catch (error) {
    console.error('Error:', error.message);
}
Click "Run" to see output...
axios Library (wraps fetch) 
// axios automatically parses JSON, handles errors better
try {
    const { data } = await axios.get('https://jsonplaceholder.typicode.com/posts/1');
    console.log('Success!', data);
} catch (error) {
    console.error('Error:', error.message);
}

Feature Comparison

Feature XMLHttpRequest fetch() axios
Syntax Callback-based Promise-based Promise-based
JSON parsing Manual: JSON.parse() Manual: response.json() Automatic
Error handling Check status manually Check response.ok manually Throws on 4xx/5xx
Timeout xhr.timeout = 5000 AbortController (complex) { timeout: 5000 }
Interceptors No No (manual) Yes (built-in)
Browser support All (including IE6) Modern only Depends on fetch
Size Built-in Built-in ~11KB (extra download)

Which should I use?

  • fetch() — Default choice for modern projects
  • axios — If you need interceptors, better error handling, or timeout support
  • XMLHttpRequest — Only if supporting ancient browsers (rare today)

POST Request Example (Like Sending Payment Data)

POST with fetch() 
const response = await fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        title: 'Payment Request',
        amount: 1000,
        customer: 'test@example.com'
    })
});

const data = await response.json();
console.log('Created:', data);
