3. Now change the origin (the real experiment)

Serve this same file from two different ports and press Send on each:

# allowed by the Django settings
python3 -m http.server 5500     ->  http://127.0.0.1:5500/cors_demo.html    ✅ works

# NOT in CORS_ALLOWED_ORIGINS
python3 -m http.server 5501     ->  http://127.0.0.1:5501/cors_demo.html    ❌ blocked

Run those from this code/ folder. Nothing about the request changed — only who is asking.

4. Then prove it's the browser, not the server

curl -i http://127.0.0.1:8001/api/ping/        # works every time — curl ignores CORS

If the server were rejecting you, curl would fail too. It doesn't — because CORS is enforced by the browser, on the response.

What each control actually changes

  • Method / custom header — a plain GET or form-style POST is a simple request: the browser just sends it. A PUT, or any custom header, makes the browser send a preflight OPTIONS first to ask permission. Watch the Network tab: you'll see two requests instead of one.
  • Credentials — include sends cookies. The server must then reply with Access-Control-Allow-Credentials: true and name an exact origin. A wildcard * is rejected outright in this mode — that's deliberate, so "allow everyone" can never leak logged-in data.
  • Origin — the one that matters. It isn't a control here because a page cannot choose its own origin; it's decided by the URL you loaded this file from. That's exactly why it can't be faked.
