Pre-Class Quiz

Test Your Class 5 Knowledge

Before diving into REST APIs, let's review Django Models & Admin.

💡 Question 1
Your MenuItem model has 10,000 rows in production. You add this new field and run makemigrations: 
category = models.ForeignKey(Category, on_delete=models.CASCADE)
A Migration creates successfully with no prompts
B Django asks for a default value because existing rows need a category_id
C Django automatically sets all existing rows to the first Category
D The migration fails because ForeignKey cannot be added to existing tables

Explanation

When you add a NOT NULL field (which ForeignKey is by default) to a table with existing rows, Django must know what value to put in that column for those rows.

Django prompts:

  • Option 1: Provide a one-time default now
  • Option 2: Quit and add null=True or default= to the field

Safe approach: Add null=True first, migrate, backfill data, then remove null=True in a second migration.

💡 Question 2
What does on_delete=models.CASCADE mean in a ForeignKey? 
category = models.ForeignKey(Category, on_delete=models.CASCADE)
A Prevent deletion if the category has menu items
B When a Category is deleted, delete all its MenuItems too
C Set category to NULL when deleted
D Create a backup before deletion

Explanation

CASCADE = "cascade" the delete operation. If Category "Appetizers" is deleted, all MenuItems in that category are also deleted.

Other options:

  • PROTECT — Prevent deletion if related objects exist
  • SET_NULL — Set FK to NULL (requires null=True)
  • SET_DEFAULT — Set FK to default value
💡 Question 3
You added a new field is_featured = models.BooleanField() to MenuItem. What happens when you run makemigrations?
A The field is added to the database immediately
B Django asks for a default value (existing rows need a value)
C Migration succeeds silently with no prompts
D Django deletes all existing rows to add the field

Explanation

When adding a field to a table with existing rows, Django needs to know what value to put in that field for existing rows.

Best practice: Add default=False to the field definition to avoid the prompt:

is_featured = models.BooleanField(default=False)
💡 Question 4
What does this QuerySet return? 
MenuItem.objects.filter(price__lte=10, is_available=True)
A Items where price < 10 OR is_available = True
B Items where price ≤ 10 AND is_available = True
C Items where price = 10 AND is_available = True
D The first item matching any condition

Explanation

Multiple conditions in filter() are combined with AND. The lookup __lte means "less than or equal to".

Common lookups:

  • __lt = less than
  • __lte = less than or equal
  • __gt = greater than
  • __gte = greater than or equal
💡 Question 5
What does list_editable do in Django Admin? 
@admin.register(MenuItem)
class MenuItemAdmin(admin.ModelAdmin):
    list_display = ['name', 'price', 'is_available']
    list_editable = ['price', 'is_available']
A Makes all fields editable in the detail view
B Allows editing price and is_available directly in the list view
C Prevents those fields from being edited
D Creates a separate edit page for those fields

Explanation

list_editable lets you edit fields directly from the list view without clicking into each item. Great for quick updates like toggling availability or adjusting prices!

Note: Fields in list_editable must also be in list_display.

Core Concept

What is REST?

REST is a set of conventions for building APIs. It's not a technology — it's a design philosophy.

📚 REST = REpresentational State Transfer

Invented by Roy Fielding in his 2000 PhD thesis. It's a way to design web services that are simple, scalable, and predictable.

REST Principles

🔗

1. Resource-Based URLs

URLs represent things (nouns), not actions (verbs).

✓ /api/menu-items/

✗ /api/getMenuItems/

🎮

2. HTTP Methods = Actions

Use HTTP verbs to indicate what you want to do with the resource.

GET = Read
POST = Create

📦

3. Stateless

Each request contains all info needed. Server doesn't remember previous requests.

📄

4. Standard Responses

Use HTTP status codes (200, 201, 404, etc.) and consistent JSON format.

HTTP Methods (CRUD Operations)

HTTP Method CRUD URL Example Purpose
GET Read /api/menu-items/ List all items
GET Read /api/menu-items/5/ Get item #5
POST Create /api/menu-items/ Create new item
PUT Update (full) /api/menu-items/5/ Replace item #5
PATCH Update (partial) /api/menu-items/5/ Update some fields
DELETE Delete /api/menu-items/5/ Delete item #5

HTTP Status Codes

Code Meaning When to Use
200 OK Success GET, PUT, PATCH succeeded
201 Created Resource created POST succeeded
204 No Content Success, no body DELETE succeeded
400 Bad Request Invalid data Validation failed
401 Unauthorized Not logged in Missing/invalid auth token
403 Forbidden No permission Logged in but can't access
404 Not Found Resource not found Item doesn't exist
500 Server Error Server crashed Bug in your code

REST vs Non-REST (RPC-style)

Action ✗ Non-REST (RPC-style) ✓ REST
Get all items POST /getMenuItems GET /menu-items/
Get one item POST /getMenuItem?id=5 GET /menu-items/5/
Create item POST /createMenuItem POST /menu-items/
Update item POST /updateMenuItem?id=5 PUT /menu-items/5/
Delete item POST /deleteMenuItem?id=5 DELETE /menu-items/5/
💡 Key Insight

In REST, the URL identifies the resource and the HTTP method determines the action. You don't need verbs in URLs!

Core Concept

What are Serializers?

Serializers convert complex data (like Django models) to JSON, and validate incoming JSON data.

The Problem: Models Aren't JSON

😱 This doesn't work!
from django.http import JsonResponse
from .models import MenuItem

def menu_list(request):
    items = MenuItem.objects.all()
    return JsonResponse(items)  # ERROR! Can't serialize QuerySet
😱 TypeError: Object of type QuerySet is not JSON serializable

Django models are Python objects. JSON only understands strings, numbers, lists, and dictionaries.

The Solution: Serializers

🗃
Django Model
Python object
→
🔄
Serializer
Converts data
→
📦
JSON
API response

Serializers Do Two Things

📦

1. Serialization

Convert Python objects → JSON (for API responses)

# Model → JSON
item = MenuItem.objects.get(id=1)
serializer = MenuItemSerializer(item)
serializer.data
# {'id': 1, 'name': 'Pasta', 'price': '15.99'}
📥

2. Deserialization

Convert JSON → Python objects (for creating/updating)

# JSON → Model
data = {'name': 'Pizza', 'price': '14.99'}
serializer = MenuItemSerializer(data=data)
serializer.is_valid()  # Validate!
serializer.save()      # Create model

Creating a Serializer

menu/serializers.py
from rest_framework import serializers
from .models import MenuItem, Category


class CategorySerializer(serializers.ModelSerializer):
    class Meta:
        model = Category
        fields = ['id', 'name', 'description']


class MenuItemSerializer(serializers.ModelSerializer):
    # Show category name instead of just ID
    category_name = serializers.CharField(source='category.name', read_only=True)

    class Meta:
        model = MenuItem
        fields = [
            'id',
            'name',
            'description',
            'price',
            'is_available',
            'category',        # FK ID (for writing)
            'category_name',   # Name (for reading)
        ]

ModelSerializer vs Serializer

Aspect Serializer ModelSerializer
Field definitions Manual (you define each field) Automatic (from model)
create() / update() You write them Automatic
Use when Custom data structures Working with models (99% of cases)
Code required More Less

Validation

Adding custom validation
class MenuItemSerializer(serializers.ModelSerializer):
    class Meta:
        model = MenuItem
        fields = ['id', 'name', 'price', 'is_available']

    def validate_price(self, value):
        """Price must be positive"""
        if value <= 0:
            raise serializers.ValidationError("Price must be greater than 0")
        return value

    def validate(self, data):
        """Cross-field validation"""
        if data.get('is_available') and data.get('price', 0) == 0:
            raise serializers.ValidationError(
                "Available items must have a price"
            )
        return data
💡 Validation Methods
  • validate_<field_name>() — Validate a single field
  • validate() — Validate multiple fields together

Three Ways to Write Views

Approach Abstraction Level Code Required Best For
@api_view Low (function) Most Custom logic
APIView Medium (class) Medium Custom + organization
ViewSet High (automatic) Least Standard CRUD (90% of cases)

Option 1: @api_view Decorator

menu/views.py - Function-based view
from rest_framework.decorators import api_view
from rest_framework.response import Response
from rest_framework import status
from .models import MenuItem
from .serializers import MenuItemSerializer


@api_view(['GET', 'POST'])
def menu_item_list(request):
    """List all items, or create a new item."""
    if request.method == 'GET':
        items = MenuItem.objects.all()
        serializer = MenuItemSerializer(items, many=True)
        return Response(serializer.data)

    elif request.method == 'POST':
        serializer = MenuItemSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)


@api_view(['GET', 'PUT', 'DELETE'])
def menu_item_detail(request, pk):
    """Retrieve, update, or delete a menu item."""
    try:
        item = MenuItem.objects.get(pk=pk)
    except MenuItem.DoesNotExist:
        return Response(status=status.HTTP_404_NOT_FOUND)

    if request.method == 'GET':
        serializer = MenuItemSerializer(item)
        return Response(serializer.data)

    elif request.method == 'PUT':
        serializer = MenuItemSerializer(item, data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    elif request.method == 'DELETE':
        item.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)

Option 2: APIView Class

menu/views.py - Class-based view
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status


class MenuItemList(APIView):
    """List all items, or create a new item."""

    def get(self, request):
        items = MenuItem.objects.all()
        serializer = MenuItemSerializer(items, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = MenuItemSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)


class MenuItemDetail(APIView):
    """Retrieve, update, or delete a menu item."""

    def get_object(self, pk):
        try:
            return MenuItem.objects.get(pk=pk)
        except MenuItem.DoesNotExist:
            return None

    def get(self, request, pk):
        item = self.get_object(pk)
        if not item:
            return Response(status=status.HTTP_404_NOT_FOUND)
        serializer = MenuItemSerializer(item)
        return Response(serializer.data)

    def put(self, request, pk):
        item = self.get_object(pk)
        if not item:
            return Response(status=status.HTTP_404_NOT_FOUND)
        serializer = MenuItemSerializer(item, data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    def delete(self, request, pk):
        item = self.get_object(pk)
        if not item:
            return Response(status=status.HTTP_404_NOT_FOUND)
        item.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)

Option 3: ViewSets (Recommended)

menu/views.py - ViewSet (minimal code!)
from rest_framework import viewsets
from .models import MenuItem, Category
from .serializers import MenuItemSerializer, CategorySerializer


class CategoryViewSet(viewsets.ModelViewSet):
    """
    A ViewSet for viewing and editing categories.
    Provides: list, create, retrieve, update, destroy
    """
    queryset = Category.objects.all()
    serializer_class = CategorySerializer


class MenuItemViewSet(viewsets.ModelViewSet):
    """
    A ViewSet for viewing and editing menu items.
    """
    queryset = MenuItem.objects.all()
    serializer_class = MenuItemSerializer
🚀 That's it! 10 lines of code gives you full CRUD!

ViewSets automatically provide: list, create, retrieve, update, partial_update, destroy.

URL Configuration with Routers

menu/urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from . import views

router = DefaultRouter()
router.register('categories', views.CategoryViewSet)
router.register('menu-items', views.MenuItemViewSet)

urlpatterns = [
    path('api/', include(router.urls)),
]

Testing Your API

DRF comes with a beautiful browsable API for testing.

1. Browsable API (built-in)

Just visit your API URL in a browser! DRF renders a nice interface.

🌐 Visit: http://127.0.0.1:8000/api/menu-items/

You'll see a web interface where you can:

  • View JSON responses formatted nicely
  • Submit POST/PUT requests using forms
  • Test filters and search

2. Using curl (Terminal)

Terminal
# GET - List all items
curl http://127.0.0.1:8000/api/menu-items/

# GET - Get single item
curl http://127.0.0.1:8000/api/menu-items/1/

# POST - Create new item
curl -X POST http://127.0.0.1:8000/api/menu-items/ \
  -H "Content-Type: application/json" \
  -d '{"name": "New Pizza", "price": "12.99", "category": 1}'

# PUT - Update item
curl -X PUT http://127.0.0.1:8000/api/menu-items/1/ \
  -H "Content-Type: application/json" \
  -d '{"name": "Updated Pizza", "price": "13.99", "category": 1}'

# DELETE - Delete item
curl -X DELETE http://127.0.0.1:8000/api/menu-items/1/
